# Ротация общих токенов без простоя

Между ботом и CRM ходят два разных секрета, каждый в одну сторону:

| Секрет | Кто хранит | Направление | Где проверяется |
|---|---|---|---|
| `BOT_INTERNAL_TOKEN` (+ `BOT_INTERNAL_TOKEN_NEXT`) | бот принимает, CRM отправляет | CRM → бот (`/internal/*`) | `smilekit_bot/api.py::_require_auth` |
| `CRM_INTERNAL_TOKEN` | бот отправляет, CRM принимает | бот → CRM (`crm.py`) | на стороне CRM |

Механика одна и та же: **принимающая сторона временно принимает два токена**,
отправляющая переключается на новый, затем старый убирается. Ни один запрос
не получает 403 в процессе. Ожидаемое время — меньше 10 минут (два-три
редеплоя по 1–3 минуты каждый).

## Ротация `BOT_INTERNAL_TOKEN` (принимает бот, шлёт CRM)

1. Сгенерировать новый секрет (например `python -c "import secrets; print(secrets.token_urlsafe(32))"`).
2. **Бот (Railway):** добавить переменную `BOT_INTERNAL_TOKEN_NEXT=<новый>`,
   `BOT_INTERNAL_TOKEN` не трогать. Дождаться редеплоя. С этого момента бот
   принимает оба токена (`hmac.compare_digest`, без раннего выхода).
3. **CRM:** заменить значение, которое она шлёт в `x-internal-token`, на новый.
   Дождаться редеплоя. Проверить: `/internal/settings` из CRM отвечает 200.
4. **Бот (Railway):** `BOT_INTERNAL_TOKEN=<новый>`, `BOT_INTERNAL_TOKEN_NEXT` —
   удалить (или оставить пустым). Дождаться редеплоя. Старый токен больше не
   принимается.

Откат на любом шаге: CRM возвращает старое значение — бот ещё принимает
его вплоть до шага 4.

## Ротация `CRM_INTERNAL_TOKEN` (принимает CRM, шлёт бот)

Зеркально: CRM должна поддерживать свой `*_NEXT` (или эквивалент) на приёме.

1. **CRM:** добавить принимаемый второй токен `<новый>` рядом с текущим.
2. **Бот (Railway):** `CRM_INTERNAL_TOKEN=<новый>`. Дождаться редеплоя.
   Проверить в логах бота, что заказы/сделки уходят без 401/403
   (`crm.py` пишет `CRM ... failed` при ошибке).
3. **CRM:** убрать старый токен из принимаемых.

На стороне бота ничего, кроме значения `CRM_INTERNAL_TOKEN`, менять не нужно.

## Правила

- Секреты только в переменных окружения Railway/CRM — никогда в git,
  `.env.example` содержит только имена.
- Пустой `BOT_INTERNAL_TOKEN_NEXT` игнорируется: пустой заголовок ничему
  не равен, вход без токена всегда 403.
- `/internal/health` без токена — как и раньше.
